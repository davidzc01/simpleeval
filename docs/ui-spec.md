# simpleEval · UI 设计与规范

| 项目 | 内容 |
|---|---|
| 版本 | v0.1（一稿，待评审） |
| 制定日期 | 2026-08-18 |
| 提炼来源 | `UI规范-企业信息管理平台 v1.1`（方法论与结构参照）、LangSmith / Langfuse / Braintrust 同类产品交互调研（2026-08） |
| 适用范围 | simpleEval Web UI 全部页面 |
| 基调 | 开发者工具风 · 中性灰底 · 单强调色 · 暗色代码区 · 高信息密度 |

> **与政务风规范的关系**：本文档沿用附件规范的结构方法论（设计令牌 → 布局 → 组件配方 → 交互范式 → 已验证的坑 → 自检清单），但**视觉令牌全部重设**。理由：simpleEval 的受众是开发者（GitHub 开源项目、面试作品集），政务风的品牌蓝渐变体系会让它看起来像内部管理系统；DevTool 的审美预期是克制、工程感、代码友好。结构是资产，皮肤要换。

---

## 0. 设计原则（五条，排序即优先级）

1. **Run 是核心对象**：一切视图围绕"一次评测"组织。LangSmith / Langfuse / Braintrust 的共同骨架都是 `Run 列表 → Run 详情 → 逐 case 下钻`，simpleEval 沿用。
2. **质量信号与成本信号同屏**：pass rate 必须和 token、latency 出现在同一个视图里。只给分数不看成本，等于把"每万 token 完成率"这个差异化卖点扔了。
3. **配置即代码区**：base_url、prompt、JSONPath、header 都是开发者资产，一律等宽字体 + 暗色块呈现，不伪装成普通表单文本。
4. **长任务先落库、后展示**：发起评测立即返回，任务在服务端跑，页面关掉不影响。UI 永远通过"任务状态"间接观察后端，不阻塞等待。
5. **密钥默认不可见**：所有 secret 类字段 masked 显示、不回显、可切换可见性，界面截图不泄漏。

## 4. 页面规格

### 4.1 Projects 列表（`/`）

```
[+ 新建 Project]                                     [搜索框]
┌────────────────────────────────────────────────────────────┐
│ 名称       │ 最近评测      │ pass rate │ token │ 趋势  │ 操作 │
├────────────────────────────────────────────────────────────┤
│ ● demo-    │ 3 分钟前      │ 87.5%    │ 42.3K │ ▁▃▅▇ │ ⋯   │
│   project  │ #run-08      │ (+2.1%)  │       │      │     │
└────────────────────────────────────────────────────────────┘
```

- 列：名称 / 最近评测（相对时间 + run id，可点）/ pass rate（含环比 delta）/ 总 token / **迷你趋势 sparkline（近 8 次 run 的 pass rate）** / 操作。
- 空态：「还没有 Project，点击右上角新建——配置一个 Judge + 一个被评测 API 就能跑第一次评测」。
- 新建弹窗：name + task_shape 下拉，其余配置进详情页填。

### 4.2 Project 概览（`/p/:pid` 概览 tab）

```
┌──────┬──────┬──────┬──────┬──────┬──────┐
│ pass  │总 token│P50   │P95   │每万token │ 失败 │
│ rate │       │延迟  │延迟  │完成率    │ case │
│ 87.5%│ 42.3K │ 1.2s │ 4.8s │ 20.7    │  2   │
└──────┴──────┴──────┴──────┴──────┴──────┘
┌─────────────────────────────────────────┐
│ 变化趋势（近 N 次 run）                   │
│  ── pass rate（左轴）  ── token 成本（右轴）│
│  [折线 + 柱组合图，无彩虹色]              │
└─────────────────────────────────────────┘
┌─────────────────────────────────────────┐
│ 最近一次评测 #run-08 · 3 分钟前          │
│ [4 个 mini 指标] [查看完整报告 →]        │
└─────────────────────────────────────────┘
```

- 指标卡固定六枚，对应 `EvalSummary` 全字段（pass_rate / total_token / latency_p50 / latency_p95 / token_per_pass / failed 数）。**每万 token 完成率单独强调**（accent 色描边卡），它是差异化指标。
- 趋势图：单图双轴可接受（质量 vs 成本本来就是两个量级），但 pass rate 用折线、token 用浅柱，颜色固定 accent + 灰，禁止多系列彩虹。
- **采样稳定性卡**（新，`GET /projects/{pid}/sampling`）：

```
┌─────────────────────────────────────────┐
│ 采样稳定性（基于全部 N 次 run）            │
│  1.0 ┤●─────────●  pass@k（潜力）        │
│  0.8 ┤      ●    ●  pass^k（稳定）        │
│  0.6 ┤            ●                     │
│      └─────┬─────┬─────┬── k           │
│            1     2     3                 │
│  两线夹缝宽度 = 不确定性；coverage < 阈值  │
│  的 k 点标灰 + 「该 k 还需 X 次 run」提示  │
└─────────────────────────────────────────┘
```

- 两条线同图，pass@k 永远 ≥ pass^k；k 固定 1/2/3。夹缝窄=稳定，宽=靠摇。
- `coverage`（n≥k 的 case 数）低于 60% 时该点标灰并注「采样不足」；`total_runs: 0` 时整卡空态：「跑两次评测后这里会显示采样稳定性」。
- 评测集结构变动会稀释 case_name 对齐，卡底固定注脚：「基于 case_name 跨 run 对齐，评测集改动可能稀释结果」。
- 最近 run 卡：显示 4 个 mini 指标 + 通过/失败比 + 查看完整报告入口。

### 4.3 评测集管理（`/p/:pid` 评测集 tab）

```
[⤒ 上传评测集] [⇩ 导出 CSV] [⇅ 覆盖当前评测集]        [搜索 case]
┌──────────────────────────────────────────────────────────────┐
│ □ │ case 名        │ 输入(截断) │ 评测类型 │ 期望/判据 │ 状态 │ 操作 │
├──────────────────────────────────────────────────────────────┤
│ ☑ │ 退款政策-精确   │ 你们支持… │ tag exact│ 支持，7天…│ 启用 │ 编辑⋯│
│ ☑ │ 回复含联系方式  │ 我想投诉… │ tag contains│ 客服    │ 启用 │      │
│ ☐ │ 态度友好-LLM   │ 你们的产品…│ tag judge │ 判据见弹层│ 禁用 │      │
└──────────────────────────────────────────────────────────────┘
                                  [新增用例] [批量禁用] [删除选中]
```

- **上传**：接受 `.csv / .json`；拖拽区 + 文件格式说明；上传前弹「覆盖 or 合并」选择（默认合并，覆盖需二次确认，§5.3）。
- **手动添加（决议 2026-08-19）**：表单逐条填写，不提供 JSON 文本域——需要手写 JSON 的用户直接走文件导入。表单字段与用例编辑器一致（case_name / input / eval_type 切换显示 expected 或 requirement / eval_params 示例模板），「添加到待导入列表」逐条累积，最后与文件导入共用同一套 preview→confirm 流程。
- **导出**：CSV（Excel 兼容，带 BOM），列与表格一致，`eval_params` 序列化为 JSON 字符串。
- **用例 CRUD**：
  - 新增/编辑走弹窗：case_name / input（多行文本域，等宽）/ expected_output 或 output_requirement（按 eval_type 二选一显示）/ eval_type 下拉 / eval_params（JSON 编辑区，按 eval_type 给示例模板）。
  - **禁用**：状态列 toggle，禁用后 case 保留但在下次 run 中被跳过（评测集仍导出、可追溯）。行置灰。
  - **硬删除**：红色入口 + 二次确认 + 影响说明（"删除后无法恢复，历史 run 中该 case 的结果保留"）。支持多选删除。
  - 行内 input/expected 超 80 字符截断，hover 或点击展开完整内容（浮层内等宽字体）。
- 表格需横向滚动：沿用政务规范 §8.1 的 `.tscroll` 解法（浮层放卡片头，滚动下沉到表格外层）。

### 4.4 配置页（`/p/:pid` 配置 tab）

三段式：**Target API** → **响应映射** → **LLM Judge**。卡片依次排列，各自可折叠。

#### 4.4.1 Target API 配置

```
模式切换：[ OpenAI Compatible | 自定义 API ]  ← tab 控件（决议 2026-08-19）

─ OpenAI Compatible tab ───────────────────────────
base_url      [https://api.example.com/v1        ]  (mono) 必填
api_key       [                             👁   ]  (mono) 选填：留空 = 不带 Authorization 头（自托管网关）
model         [deepseek-chat                     ]  (mono) 必填，保存时阻断校验
请求模板（折叠·高级）[JSON 编辑区，默认 {"messages":[{"role":"user","content":"{input}"}]}]
auth（折叠·高级）    [与下方自定义 tab 相同的四选一 + kv 编辑器]

─ 自定义 API tab ──────────────────────────────────
base_url      [https://fastgpt.example.com/api    ]  (mono) 必填
认证          [○ 无  ○ Bearer Token  ○ API Key(header)  ○ Cookie  ○ 自定义 Headers]
  └ 动态区：Bearer → [token 输入框(密码型+可见切换)]
            API Key → [header 名] [值]
            Cookie → [kv 行编辑器，可多条]
            自定义 Headers → [kv 行编辑器，可多条]
请求模板      [JSON 编辑区，必填，保存时阻断校验]
              {input} / {case_name} / {task_shape} 为可替换变量
响应解析      [指向 4.4.2 卡片，建议必配；留空 = 完整原文兑底]

[测试连接]  ← 发一个最小请求，返回：✓ 200 · 1.2s · 12 tokens（或 ✗ 错误详情）
```

- **两种模式的本质区别只有一条：请求体谁构造。** openai_compatible 由工具构造（标准 messages 模板 + model 注入），custom 由用户模板全权构造（**不注入 model、不补 messages**）。响应解析永远是独立配置，不随模式切换。
- auth 方式切换时动态区即时替换，已填值按方式分组记忆（切走不丢）；两种 tab 共享同一份 auth 配置。
- 校验规则（保存时阻断，前后端双保险）：openai_compatible → model 必填；custom → request_template 必填。api_key 在两种模式下均可留空。
- 旧数据零迁移：无 `api_type` 字段的项目默认 `openai_compatible`。
- **测试连接按钮是必配项**：这是配置页的"保存前验证"，防止把错误的配置带到 run 里烧 token。结果内联展示在按钮右侧，成功绿色 / 失败红色 + 原始错误。
- 所有 secret 字段：`type=password` + 右侧眼睛 toggle；**服务端永不回显明文**（返回 `•••`）。

#### 4.4.2 响应解析（输出与 token 路径配置）

```
说明：被评测 API 的返回结构各异。这里配置：哪个路径是输出结果、哪些路径/字段算 token 消耗。
不设解析器类型——给路径走精确提取，给字段名走全树递归求和。详见 docs/response-parsing-design.md

输出路径（按序 fallback，第一个命中生效）
  [$.choices[0].message.content      ] [×]
  [$.data[-1].pluginOutput.text     ] [×]
  [+ 添加路径]      [⌁ 从样例响应点选生成路径]

Token 统计（二选一，paths 优先于 fields）
  ○ 路径求和：[$.usage.total_tokens        ] [×]
              [+ 添加路径]
  ○ 字段递归：[total_tokens                ] [×]
              [toolCallInputTokens          ] [×]
              [+ 添加字段]
     过滤（可选）：[moduleType] = [tools]

[用样例返回测试解析] → 粘贴一段真实返回 JSON：
  左側 JSON 树（可点选节点 → 自动生成路径）｜右侧提取结果 + token 计数
```

- **样例响应点选是核心辅助**：粘贴一段真实返回，JSON 树展开，点击任意节点自动生成 JSONPath 填入路径框。用户不手写 JSONPath。
- 路径非法即时标红（行级校验）；「测试解析」面板显示：输出提取结果（或 ✗ 未命中列表）+ token 计数（或 ⚠ token 字段未命中 → `token_missing` 提示）。
- 全部留空 = 默认行为（完整返回作为 actual_output，不统计 token），与 MVP 兼容。
- 交互语义固定不可配：`output_paths` 永远按序 fallback；`token_paths` 永远命中求和；`token_fields` 永远全树递归求和。**语法决定语义，无 mode 开关。**

## 5. 核心交互范式

### 5.1 长任务范式（发起评测）★

| 要素 | 规格 |
|---|---|
| 后端 | run 落库即返回 `run_id`，任务入队执行（FastAPI BackgroundTasks 起步，v2 可换队列） |
| 前端 | 跳转 Run 详情页，**2s 间隔轮询** `GET /r/:rid`，指数退避封顶 10s |
| 静默更新 | 轮询数据只做差异合并：新增 case 行追加、数字平滑过渡、已渲染行不闪骨架 |
| 中断恢复 | 关闭页面不终止任务；重开任意页面，侧栏/顶栏任务指示器显示 running 数，点 run 恢复进度视图 |
| 完成 | Toast + 状态转绿；若页面已关闭，下次进入 Project 概览时"最近评测"卡显示新结果 |
| 失败兜底 | 单 case 异常不终止整个 run：标记 failed + 错误信息进 case 详情；run 级异常（如 Judge 全挂）置 failed 状态 + 错误横幅 |

轮询节流原则：**任务状态是唯一事实源，UI 永不自行推算结果。**

### 5.2 密钥与敏感信息

- secret 字段一律密码型输入 + 眼睛 toggle；服务端 API 返回 `masked: true`，永不回显。
- 导出/分享/截图安全：Run 详情和对比视图不含任何密钥。
- `.env` 注入提示：Target/Judge 配置页底部 notice——"生产建议用环境变量注入（后续版本），当前配置仅存本地 JSON"。

### 5.3 危险操作三要素（沿用政务规范 §5.2，措辞调整）

| 要素 | 要求 |
|---|---|
| 红色入口 | 硬删除、覆盖评测集、清空历史 |
| 二次确认 | 弹窗展示对象名称 + 影响范围 |
| 风险说明 | 写明会丢什么 + 可规避动作（例："覆盖将丢弃当前评测集全部 N 条用例，建议先导出 CSV"） |

### 5.4 三态必备

- 加载：表格区骨架屏（灰条），**轮询刷新不触发骨架屏**（区别于初次加载）。
- 空态：具体文案 + 引导按钮（"还没有评测集，上传一份或从示例开始"）。
- 失败：Toast 错误 + 行内重试；run 级失败显示错误横幅。

## 6. UI 需求 → 后端契约缺口 ★（本稿最重要的一节）

当前 `app/models.py` 与上述 UI 需求之间存在硬缺口。**UI 规格本身不改后端，但每一项都必须有对应字段/接口，否则前端只能做假数据。** 按优先级排列：

| # | UI 需求 | 现状 | 需要的后端变更 | 影响 |
|---|---|---|---|---|
| 1 | 测试 API 支持 bearer/header/cookie 多配置 | `TargetConfig` 只有 `base_url/api_key/model` | `auth: {type: none\|bearer\|api_key\|cookie\|headers, ...}` 结构化字段 | models.py + runner.py |
| 2 | 返回解析（输出路径 + token 路径/字段可配置） | 无 | `TargetConfig` 增 `response_parsing`（四键模型，见 `docs/response-parsing-design.md`），runner 执行前提取 | models.py + parser.py + runner.py |
| 3 | Judge Prompt 可配置 | `judge_config` 无 prompt 字段 | `JudgeConfig` 增 `prompt_template` | models.py + judge.py |
| 4 | 用例禁用/硬删除 | `EvalCase` 无状态字段 | `EvalCase` 增 `enabled: bool = True`；删除=物理删（JSON 存储下软删需快照策略） | models.py + 评测集读写 |
| 5 | 最近测试/趋势/历史列表 | `EvalRun` 是瞬时对象，无持久化 | run 落库：`data/runs/{project_id}/{run_id}.json`，增 `GET /projects/:pid/runs`、`GET /runs/:rid` | **新增存储层** |
| 6 | 任务不因关页面打断 + 进度 | `/api/run` 同步阻塞，跑完才返回 | 任务队列：BackgroundTasks 起步，`run.status: queued\|running\|completed\|failed` | main.py 架构调整 |
| 7 | 测试连接 / 测试 Judge / 测试映射 | 无 | `POST /api/test-connection`、`POST /api/test-judge`、`POST /api/test-mapping` 三个轻量接口 | 新增 3 个端点 |
| 8 | 历史导出、评测集 CSV 导入导出 | 无 | 导入/导出工具函数（CSV↔JSON，BOM 处理） | 新增 util |

**建议落地顺序**：#5+#6 先行（没有 run 持久化和任务队列，概览页和历史页全是空的），然后 #1/#2/#3（配置能力），最后 #4/#7/#8（体验层）。这样每一步都有可演示的闭环。

## 7. 已验证/预见的坑

| 坑 | 规避 |
|---|---|
| 长输出撑爆表格/卡片 | 输出区一律等宽 + 截断 500 字符 + 展开；表格单元格 `max-width` + ellipsis + 浮层预览 |
| 轮询导致前端抖动 | 差异合并渲染；数字用 `tabular-nums` 防宽度跳动；禁止轮询触发骨架屏 |
| LLM 输出含 HTML/JS 注入 | 输出渲染一律 `textContent`，绝不用 innerHTML；代码区高亮用文本层叠方案 |
| CSV 中文乱码（Excel 打开） | 导出加 UTF-8 BOM；导入兼容 BOM |
| JSONPath 误提取导致全部 case 假失败 | 「测试映射」面板 + 映射变更后发起评测弹窗里显示"映射最近一次校验时间" |
| 密钥出现在页面截图/分享 | §5.2 全量 masked；Run 详情零密钥 |
| run id 泄漏 / 越权 | 本地单用户工具可暂缓，但路由不显示绝对路径 |
| 宽表格 + 下拉浮层互相裁剪 | 沿用政务规范 §8.1 `.tscroll` 解法，浮层放卡片头 |
| 轮询打爆本地服务 | 指数退避 + 页面 `visibilitychange` 隐藏时暂停轮询，恢复时立即补拉一次 |
| 时区混乱（created_at） | 存储 UTC ISO，展示统一本地时区相对时间 |
